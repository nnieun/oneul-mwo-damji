# 구현 및 검증 현황

## 구현된 기능

- SQLite 스키마 버전 관리, 기존 데이터 보존, 상품 18종·레시피 10종 시드.
- 장바구니 저장·조회·수량 변경·삭제, 가격 스냅샷과 예상 금액 계산.
- 동일 담기 요청 재전송의 중복 반영 방지 및 후보 확정 트랜잭션.
- OpenCV 단일 캡처 작업, MJPEG 미리보기, 시작·종료·오류 안내.
- Roboflow HTTP 추론 어댑터, 모델 라벨 매핑, 시간 초과·잘못된 응답 처리.
- 후보 생성·중복 제거·수정 확정·제외·만료 검증.
- 필수·선택 식재료를 구분하는 장바구니 기반 추천과 조리 순서.
- React 실제 API 연동, 새로고침 복원, 실패한 담기 요청 재확인, 더미 모드 표시.
- Swagger UI, 내보낸 OpenAPI 명세, 환경 설정 예시 및 실행 안내.

## 검증 결과

- 초기 기존 테스트: SQLite 스레드 문제로 5개 오류. 원본 실패 로그를 F00에 보존.
- 수정 후 전체 pytest: 41 passed, 2 skipped.
- 미실행 2개: 실제 카메라, 실제 카메라와 Roboflow 모델 결합 검증.
- 브라우저 통합 테스트: 더미 영상 스캔, 후보 담기·제외, 응답 유실 후 중복 없는 재시도, 추천 상세, 수량·삭제·금액, 새로고침 복원, 카메라 종료 통과.
- 브라우저에서 390px 모바일 폭 가로 넘침과 JavaScript 실행 오류가 없음을 확인.
- TypeScript 검사 및 프로덕션 빌드는 별도 프론트 검증 결과 파일에 기록.

각 실행의 실제 명령·기준 커밋·항목별 결과는 [test-results](test-results/)에 있습니다. 기능 커밋은 로컬에 생성했으며 원격 저장소에 푸시하지 않았습니다.

## 실패 원인과 수정

- SQLite 공유 인메모리 연결을 작업별 연결로 분리하고 수명 유지 연결을 별도로 관리했습니다.
- 마이그레이션 도중 실패하면 스키마·시드·버전이 함께 롤백되도록 수정하고 회귀 테스트를 추가했습니다.
- 최초 브라우저 테스트에서 JSON BOM 인코딩으로 개발 서버 시작이 실패했습니다. UTF-8 BOM을 제거한 뒤 동일 브라우저 테스트를 재실행하여 통과했습니다. 실패·재실행 기록을 모두 보존했습니다.
- 기존 의존성의 Starlette/AnyIO 조합에서 DeprecationWarning 1개가 출력됩니다. 테스트 실패는 아닙니다.

## 별도 검증이 필요한 항목

실제 카메라 장치와 Roboflow 학습 모델 ID·API 키는 이번 자동 검증에서 사용하지 않았습니다. 실제 모드 연결 코드는 구현했으며 설정 후 하드웨어 테스트와 시연을 진행해야 합니다. 상품별 인식 정확도·mAP50 0.80 목표 달성 여부는 측정하지 않았습니다.

모델이 준비되지 않았더라도 더미 모드 또는 수동 상품 선택으로 장바구니·추천 흐름을 확인할 수 있습니다. 실제 결제, 다중 카트 운영, 재고 연동은 계획대로 제외했습니다.
