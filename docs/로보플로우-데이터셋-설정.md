# Roboflow 데이터셋 설정 권장안

`sang-rqj4u/ozm-4-yolov8n-t1` (YOLOv8n, 10개 클래스: apple, bread, carrot, egg, galic, l_onion, onion, raw_pork, shrimp, sliced_ham) 학습용 데이터셋을 준비할 때의 Train/Test Split, Preprocessing, Augmentation 설정에 대한 권장안입니다. 실제 학습·검증은 아직 진행하지 않았으며, 이 프로젝트의 사용 조건(브라우저 카메라로 한 프레임에 물건 하나를 근접 촬영, 실시간 추론, 가벼운 nano 모델)을 근거로 한 사전 의견입니다.

## 전제 조건

- 이 앱은 사용자가 손에 든 식재료 하나를 카메라 앞에 대고 스캔하는 방식입니다. 즉 학습 이미지도, 실제 추론 프레임도 **한 화면에 물건 하나가 크게 나오는 근접 사진**이 기준이 됩니다.
- 클래스가 대부분 **색이 중요한 단서인 식재료**(사과=빨강, 당근=주황, 마늘/양파=흰색, 돼지고기/슬라이스햄/새우처럼 붉은 계열 살구·분홍색 등)라서, 색을 크게 바꾸는 증강은 오히려 클래스 구분을 방해할 수 있습니다.
- YOLOv8n은 파라미터가 적은 경량 모델이라 너무 공격적인 증강을 쓰면 학습이 오히려 불안정해질 수 있습니다. 데이터가 적을수록(총 778장, 클래스당 평균 62~78장) 증강으로 다양성을 보완하는 것은 맞지만, 강도는 보수적으로 가는 편이 안전합니다.

## 1. Train/Test Split — 80% / 10% / 10%는 유지 권장

**근거**
- 전체 778장(Train 622 / Valid 78 / Test 78)처럼 데이터가 적은 편일 때는 Valid·Test 비율을 더 낮추면(예: 90/5/5) 평가 표본이 너무 작아져 정확도·재현율 수치의 신뢰도가 떨어집니다. 반대로 Valid·Test를 늘리면(예: 70/15/15) 안 그래도 부족한 학습 데이터가 더 줄어듭니다.
- 10개 클래스에 Test 78장이면 클래스당 평균 7~8장 수준입니다. 이는 "합격/불합격을 가르는 정밀 지표"로 쓰기엔 얇지만, 지금 단계(모델이 실제로 쓸만한지 가늠하는 1차 검증)에는 충분합니다.

**의견**
- 80/10/10 그대로 사용해도 됩니다. 다만 클래스별 장수 편차가 큰 게 문제이지 비율 자체가 문제는 아닙니다 — `galic`, `raw_pork`, `shrimp`처럼 상대적으로 촬영이 늦게 추가됐을 클래스는 Valid/Test에 최소 1~2장이라도 고르게 배정됐는지(클래스당 이미지 수를 확인해서) 점검하는 걸 더 우선순위로 두는 게 좋습니다. Roboflow가 무작위 분할 시 특정 클래스가 Test에 0장 배정되는 경우가 실제로 있습니다.
- 이후 실제 상품 스캔으로 이미지가 더 쌓이면(수백~수천 장 규모) 그때는 90/5/5처럼 Test 비율을 낮춰도 무방합니다.

## 2. Preprocessing

| 옵션 | 권장 | 근거 |
| --- | --- | --- |
| Auto-Orient | **ON (유지)** | 휴대폰·웹캠에서 오는 이미지의 EXIF 회전 정보 불일치를 바로잡는 안전한 기본 옵션입니다. 끌 이유가 없습니다. |
| Resize 640×640 | **ON, 단 "Stretch to" → "Fit within(검은 여백)"으로 변경 권장** | 아래 별도 설명. |
| Grayscale | OFF (유지) | 색이 핵심 구분 단서인 식재료가 많아 흑백 변환은 정보 손실이 큽니다. |
| Auto-Contrast | 상황에 따라 선택 | 촬영 환경(조명)이 서로 다른 이미지들을 섞어 썼다면 ON이 도움이 됩니다. 비슷한 조건에서 한 번에 찍었다면 굳이 켤 필요는 없습니다(밝기 편차는 아래 Brightness/Exposure 증강으로 대응). |
| Isolate Objects | OFF (유지) | 객체 탐지(바운딩 박스 위치 학습)가 목적이므로 박스만 잘라내는 옵션은 부적합합니다(분류 전용 데이터셋에 쓰는 옵션). |
| Filter Null / Random Sample / Static·Dynamic Crop / Tile / Modify Classes / Filter by Tag | OFF (유지) | 데이터가 이미 적고, 이미지 대부분이 근접 촬영이라 타일링·크롭으로 얻을 이득이 없습니다. Filter Null은 "물건 없음(배경)" 네거티브 샘플을 의도적으로 넣었다면 절대 켜면 안 됩니다. |

**Resize를 "Stretch"가 아니라 "Fit(레터박스)"로 바꾸는 이유**

Stretch는 원본 비율을 무시하고 정사각형으로 늘려버립니다. 마늘·양파처럼 둥근 형태가 타원으로 눌리거나 늘어나면, 모양이 비슷한 클래스끼리(양파 vs 마늘, 새우 vs 슬라이스햄) 구분이 더 어려워질 수 있습니다. "Fit within"(비율 유지 + 남는 자리는 여백)으로 바꾸면 실제 사물의 비율이 보존되고, 이는 YOLO 계열이 원래 추론 시 내부적으로 쓰는 letterbox 방식과도 일치해서 학습·추론 조건 차이를 줄여줍니다.

## 3. Augmentation

**전체 방향**: 카메라 각도·거리·손으로 들고 있을 때의 회전/가림/조명 변화처럼 "실제 스캔 상황에서 자연스럽게 벌어지는 변화"는 적극적으로 넣고, 색상(Hue)·채도(Saturation)처럼 "클래스 정체성을 바꿔버릴 수 있는 변화"는 약하게 쓰거나 끄는 걸 기준으로 삼았습니다.

### 켜기를 권장

| 옵션 | 권장 값 | 근거 |
| --- | --- | --- |
| Flip – Horizontal | ON | 식재료를 좌우로 뒤집어도 같은 물건입니다. 학습 데이터를 사실상 2배로 늘리는 효과가 있고 부작용이 거의 없습니다. |
| Flip – Vertical | 선택(가능하면 ON) | 사용자가 카메라에 물건을 대는 각도가 일정하지 않아, 위아래가 뒤집혀 잡힐 가능성도 실제로 있습니다. 다만 텍스트·로고가 있는 포장 식품(식빵)은 위아래 반전이 부자연스러울 수 있어 확신이 없다면 꺼도 무방합니다. |
| 90° Rotate | ON (CW/CCW 중 하나 이상) | 대부분의 식재료는 "정방향"이 없습니다(사과, 당근, 마늘 등). 손에 들고 아무 각도로나 보여주는 실사용 조건과 잘 맞습니다. |
| Rotation ±15° | ON | 촬영 각도가 살짝 기울어지는 정도의 변화는 흔합니다. ±15°는 과하지 않은 값입니다. |
| Shear ±10° | ON (기본값 유지) | 카메라가 정면이 아니라 약간 비스듬히 보는 상황(원근 왜곡)을 흉내냅니다. 기본값 정도면 무리 없습니다. |
| Brightness ±15% | ON | 웹캠·조명 환경마다 밝기 차이가 크게 납니다. 실사용 환경 다양성 대응에 가장 효과가 큰 증강 중 하나입니다. |
| Exposure ±10% | ON | Brightness와 함께 카메라 자동노출 편차를 보완합니다. |
| Blur ≤2.5px | ON (약하게) | 실시간 캡처 프레임은 손떨림·포커스 미스로 약간 흐려질 수 있습니다. 낮은 값이라 부작용이 적습니다. |
| Noise ≤0.1% | ON (약하게) | 저가 웹캠 센서 노이즈를 흉내냅니다. 영향이 작아 켜서 손해볼 것이 없습니다. |
| Crop 0–20% | ON | 사용자가 카메라와의 거리를 다르게 잡는 상황(물건이 화면을 꽉 채우거나 작게 잡히거나)을 보완합니다. |
| Cutout 3×10% | ON | **이 앱 특성상 특히 유용합니다** — 손으로 물건을 들고 스캔하면 손가락이 물건 일부를 가리는 경우가 실제로 매우 흔합니다. Cutout이 이 부분 가림 상황을 학습에 반영해줍니다. |
| Camera Gain σ=0.05 | ON (약하게) | 주방처럼 조명이 어두운 곳에서 카메라 게인이 올라가며 생기는 노이즈를 흉내냅니다. 값이 작아 부담이 적습니다. |

### 약하게 쓰거나 끄기를 권장

| 옵션 | 권장 | 근거 |
| --- | --- | --- |
| Saturation ±25% | **끄거나 폭을 줄이기(예: ±10%)** | 돼지고기·슬라이스햄·새우처럼 붉은 계열 색조 차이로 구분되는 클래스가 있어, 채도를 크게 흔들면 클래스 간 색 차이 자체가 흐려질 위험이 있습니다. |
| Hue ±15° | **끄거나 폭을 크게 줄이기(예: ±5°)** | 색상(Hue)은 이 데이터셋에서 가장 위험한 증강입니다. 마늘의 흰색과 양파의 흰색, 당근의 주황과 다른 주황 계열 사이 색조를 흔들면 실제로 클래스가 뒤바뀌어 보일 수 있습니다. |
| Grayscale 15% | **끄기 권장** | 위와 같은 이유로 색 정보가 중요한 클래스가 많아, 일부라도 흑백으로 바꾸는 것은 득보다 실이 클 수 있습니다. 조명이 극단적으로 나쁜 환경까지 대응해야 한다면 5% 이하로 아주 낮게만 고려하세요. |
| Motion Blur 100px, 0°, 1 frame | **끄거나 값을 크게 낮추기(예: 5–10px)** | 기본값 100px는 640px 프레임 기준으로 지나치게 강합니다. 물건 형태 자체가 뭉개질 정도라 학습에 방해가 될 수 있습니다. 쓰려면 픽셀 값을 대폭 낮추세요. |
| Mosaic (4장 합성) | **끄기 권장** | 실제 추론 프레임은 항상 "물건 하나가 화면 대부분을 채우는" 구도인데, Mosaic은 작은 조각 4개를 이어붙여 여러 물체가 작게 나오는 구도를 만듭니다. 학습 분포와 실제 사용 분포가 어긋나 오히려 성능을 해칠 수 있습니다. 게다가 Ultralytics YOLOv8로 직접 학습한다면 학습 스크립트가 이미 자체적으로 online mosaic을 적용하므로, Roboflow에서 한 번 더 적용하면 중복·과증강이 됩니다. |

### Bounding Box 레벨 증강 전체 — 끄기 권장

Roboflow도 "고급 기능이며 성능을 떨어뜨릴 수 있다"고 명시한 항목입니다. 이 데이터셋은 이미지 한 장에 물건 하나, 박스 하나가 화면 대부분을 차지하는 구조라 이미지 전체에 적용하는 일반 Augmentation과 BB 레벨 Augmentation의 효과 차이가 거의 없습니다. 여러 물체가 겹쳐 있고 그중 일부만 다르게 변형하고 싶을 때 쓰는 기능이므로, 지금 단계에서는 켤 이유가 없습니다.

## 요약

- **Split**: 80/10/10 유지. 대신 클래스별 이미지 수가 고르게 나뉘었는지 확인.
- **Preprocessing**: Auto-Orient 유지, Resize는 640×640 유지하되 Stretch 대신 Fit(레터박스)로 변경.
- **Augmentation**: 기하학적 변화(Flip, Rotate, Rotation, Shear, Crop)와 조명·노이즈 계열(Brightness, Exposure, Blur, Noise, Camera Gain), 그리고 이 앱 특유의 손가락 가림 상황을 흉내내는 Cutout은 적극 사용. 색상 계열(Hue, Saturation, Grayscale)과 과도한 Motion Blur, Mosaic, BB 레벨 증강은 최소화하거나 끄기.

## 남은 과제

이 문서는 실제 학습 결과(mAP, 클래스별 confusion matrix)를 보지 않은 상태의 사전 권장안입니다. 1차 학습 후 어떤 클래스가 서로 혼동되는지(예: 마늘 vs 양파) 확인해서, 혼동이 심한 클래스 쌍이 있다면 그 원인이 된 증강(색상 계열)을 더 줄이거나, 반대로 데이터가 부족해서 생긴 문제라면 해당 클래스 사진을 더 확보하는 방향으로 조정하는 것을 권장합니다.
